# BetterDesk Enrollment

- Signal-mode Managed enrollment must create `pending_device_<peerID>` in `server_config` and deny registration until operator approval; Locked mode must deny without creating pending requests.
- Outbound session initiation (`PunchHoleRequest` / `RequestRelay`) requires an authorized initiator (#302 / #327):
  - All modes: initiator must present a valid BetterDesk **client login token** (username/password, LDAP, or OIDC) on the punch/relay message, **or** be a live registered peer in the signal peer map (UDP/WS heartbeat or TCP `RegisterPk` IP bind), **or** come from the panel Web Remote proxy. Anonymous rendezvous is refused.
  - **Login is enough for the initiator:** a valid opaque client session token authorizes PunchHole/RequestRelay in open, managed, and locked modes — the initiating client does **not** need an approved `peers` row, Windows service enrollment, or clearance of `pending_device_<id>`. Banned / soft-deleted devices remain refused.
  - Managed / locked **without** a login token: initiator must exist as an approved peer in the DB (`GetPeer`); `pending_device_<id>` alone is never enough (also rejected if that pending key still exists). Stock RustDesk clients that only start the OS service (no panel login) still need enrollment approval in managed/locked.
  - **Panel Web Remote exception:** PunchHole/RequestRelay from `PANEL_SIGNAL_PROXY_CIDRS` (default loopback `127.0.0.0/8,::1/128`) are accepted without a peer registration. The Node panel authenticates the operator (or guest) at `/ws/rendezvous` upgrade before TCP-bridging to hbbs. Split panel↔Go installs must set the console container/host CIDR. Synthetic initiator id in audit logs: `panel-web-remote`.
  - **Target reachability:** the remote peer must still be online in the signal map (typically the Windows/macOS/Linux service heartbeats). Login on the viewer does not make a stopped remote host connectable.
- Commit references for GitHub issues should use `Refs #N` (not `Fixes`) when the user wants the issue left open.
